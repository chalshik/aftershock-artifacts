### Statistic (`analysis/k3w.py`)
- **U** (`work_rate`, FILE(analysis/k3w.py:104)): uncached prompt tokens per second, Σ (prompt_tokens − cached_tokens) over ok requests, session and burst, whose first token falls in the window (the first token ends a request's prefill). It raises if an ok request has no first-token time or no prompt length. U is a mean over the whole window; its values over consecutive 300 s spans, with the lowest and the highest, are reported beside it (`reported_spans`).
- **U_off** (`reference`, FILE(analysis/k3w.py:131)): the mean of U over REG-8's five saturated cache-off runs, pinned by id (FILE(analysis/k3w.py:74): `sweep_l1pl350_pc_off` at λ = 2, 2.5, 3, 3.5, 4, the runs that give the floor 1.681 req/s, RUN(the 13 REG-8 runs, gate.reg8_zone)), each over its measured window. It raises unless exactly those five are there and valid. All five count, and they are not held to the busy precondition; r against the four runs at λ ≥ 2.5 is reported beside r.
- **r** = U over W ÷ U_off, per run. W = [burst end + 600 s, burst end + watch): [1680, 2580) s; [1680, 5580) s for REG-15; [1680, 4080) s for REG-19's runs (DERIVED from the configs: burst end 1080 s, watch 1500, 4500 and 3000 s).
- **Why r:** it contains no turn mix, no residence, no queue discipline and no think time. On synthetic servers (FILE(tests/test_k3w.py:156) onward; no run read): an all-miss first-come-first-served server reads r = 1.00 ± 0.02 at λ = 2.0 and 2.4; so does a running batch of 16 or of 64 slots and a six-fold think time; a fixed cost per turn moves r by under 0.02; a trap at 1.85 or 1.55 req/s reads 1.10 or 0.92; a work rate that differs by load fails J2.
- **Model F's own number** (`docs/model.md` M5): the trapped server works at the all-miss capacity whatever the load, so r = 1.00 and a spread of 0 between loads; with a fixed cost per turn, within 0.02 of that.
- **What r cannot see:** hits below the precondition (r subtracts cached tokens; the precondition, not J1, answers whether the state is all-miss), and prefill done twice after a preemption (each request's tokens are counted once). A run that redoes prefill is credited with less work than it did.

The function raises before `docs/decisions.md` has a line that begins as REG-19's result heading does (`## <date> · [RESULT] REG-19` with no digit after it, FILE(analysis/withheld.py:39)); a heading with another tag first that only quotes those words lifts nothing. **The code cannot tell an interim result heading from the final one, nor a heading from a pasted line that begins the same way: the guard for those is the rule that no such line is written before REG-19's final result** (stopping rule). - **A run enters** when `k1.cold_backlogged` holds in its own end window. **It is judged** only if, in W, it is
  - (a) **all-miss:** prefix reuse of later turns (`k1.reuse`) ≤ 0.05; and
  - (b) **busy:** at least one request waiting in at least 0.99 of the scrapes of W (`k3w.busy_share`, FILE(analysis/k3w.py:117)), **and the gauge covers W**: a scrape within 10 s of each end and no gap above 10 s (`load._covered`). A missing gauge is listed as "no waiting gauge in W", not as idleness.
- **What the gauge counts:** `vllm:num_requests_waiting` is the scheduler's waiting queues, the deferred requests included; a request in the running set is not counted (SOURCE(vLLM 0.32.0 vllm/v1/core/sched/scheduler.py:Scheduler.get_request_counts); SOURCE(vLLM 0.32.0 vllm/v1/metrics/loggers.py:PrometheusStatLogger.record), which adds the deferred requests back to the field that `Scheduler.make_stats` gives without them). So an engine that holds every request in its running set reads 0 and is left out, though it may be working at capacity. In the published cold spans the running set was about 30 with KV at 0.95 and 54 or more requests waiting (RUN(20261110-182920_burst_l1pl350cl_r2.0_s2, gate.reg17_gate)), so this is not expected to bite (BELIEF). **Where 10 s comes from:** the harness's own limit on a scrape gap is 2 s; 10 s lets a few scrapes be missing and not a stretch.
- **Why busy:** an engine whose line empties in part of W does less work for a reason that is not its capacity. The draft-3 review's own synthetic trace, an all-miss server with a lull, read r = 0.69 to 0.91 (FILE(docs/drafts/reviews-2026-11-13/rulef-reg21-v3-2.md), its trace a2; the committed test shows r below 0.9 for such a server, FILE(tests/test_k3w.py:201)).
- **Runs left out are listed with their reasons** (`judged.left_out`): "no later turn in W", "not all-miss in W", "no waiting gauge in W", "idle in W", each that applies; "no work rate" is given only when none of the others applies. Their r, where it exists, is in the table's rows. A run that did not enter has no row there; `reported_spans` still gives its spans and its `r_first`, which for a W of 900 s is the value r would have.
